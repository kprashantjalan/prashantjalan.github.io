Lineage QA Verification Agent

One made-up mapping can undermine trust in a whole deliverable. I built an automated review that checks every claim before it reaches stakeholders.

  • Python
  • SQLite schema registry
  • Rule engine
  • Confidence scoring

The Problem

When people and AI agents produce lineage analysis, the usual failures are plausible-looking fabrication: invented field names, made-up topic names, or an intermediate Java object listed as a “source”. Manual review couldn’t keep up, and one fabricated mapping damages trust in the whole deliverable.

What I Built

An automated QA gate that every lineage deliverable must pass before it counts as done:

  • Schema-backed field checks: every field path is verified against a schema registry that refreshes daily (tens of thousands of message fields).
  • Topic validation: each topic name is checked against the indexed topic inventory.
  • False-source detection: flags in-memory objects, DTOs and stream-processing state listed as data sources.
  • Reference checks: file paths and line numbers must actually exist.
  • Confidence scoring: HIGH, MEDIUM or LOW depending on whether a claim was verified by the database, by heuristics, or not at all.
  • Graceful degradation: falls back to heuristics if the registry is unavailable, and says so in the report.

Why This Approach

Verification has to be cheap, or people skip it. Database-backed lookups take under 50 ms per check, so the agent can run on every iteration instead of once at the end. Results are grouped by verification method, so reviewers know exactly which claims are strongly backed.

Outcomes

  • Made “no fake data” a mechanical check instead of a policy document.
  • An extraction fix (matching table/column-aware full names) removed a class of false “not found” results.
  • The agent has its own test suite and is required for every lineage project.

Lessons

Guardrails for AI output work best as fast, deterministic checks with clear pass/fail results, not as prompts asking the model to “be careful”.
