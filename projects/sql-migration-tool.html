Legacy-to-Modern SQL Migration Tool

A platform move meant hundreds of report queries had to be rewritten, with the mapping knowledge buried in spreadsheets. I turned those spreadsheets into an automatic converter.

  • Python
  • Flask
  • React
  • SQL parsing
  • Trino
  • Mapping-driven transformation

The Problem

A platform modernization moved reporting from legacy DB2/Postgres warehouses to a Trino-based lakehouse. Hundreds of existing queries had to be rewritten. Table and column names changed, dialects differ, and the mapping knowledge lived in large, messy spreadsheets maintained by several teams.

What I Built

A web tool that converts a legacy query into the target dialect automatically:

  • Mapping ingestion: cleans thousands of spreadsheet mappings. It splits multi-value cells, rejects invalid identifiers, and filters out comment text that had leaked into expression columns.
  • Table and column translation: rewrites every reference using the mapping. When one legacy column maps to several candidates, a multi-factor score picks the best one.
  • Dialect conversion: handles date functions, casts, string functions and pagination differences.
  • Safe fallbacks: an unmapped column becomes an explicit NULL AS col with a note, never an invented name.
  • Browse and search UI: lets analysts inspect mappings directly.

Why This Approach

Deterministic, mapping-driven conversion is auditable: every change can be traced to a mapping row. I validated against the mappings themselves and added a regression test for each data quality bug found in the spreadsheets.

Outcomes

  • Query conversion that used to be manual now runs in seconds, with full coverage of the mapped SQL patterns.
  • Deployed as a lightweight app bundle about 10x smaller than the full repository.
  • Later reused as the refactoring engine inside a natural-language data quality assistant.

Lessons

Most migration bugs were data bugs in the mapping source, not SQL bugs. Validating inputs strictly paid off more than clever parsing.
