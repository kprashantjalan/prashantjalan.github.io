Code Knowledge Engine for 150+ Repositories

Analysts and AI agents needed fast, precise answers about how 150+ systems handle data. I built a search layer that answers with evidence.

  • Python
  • SQLite FTS5
  • Embeddings
  • REST API
  • CLI

The Problem

Analysts and AI coding agents needed to answer questions like “which service writes this field?” or “who consumes this message stream?” across 150+ repositories in Java, Scala, Python and SQL. Grepping raw clones was slow and noisy, and it burned a lot of LLM context, because every search returned hundreds of irrelevant lines.

What I Built

A lightweight, self-hosted code knowledge service that indexes every repository once and answers questions precisely:

  • Hybrid search: full-text (FTS5) for exact names, plus semantic search for concepts (“where is margin netted?”).
  • Structural lookups: find a function or class by name, including abstract, static, interface and enum declarations.
  • Write-site index: records every place a field is assigned, including the operator, the enclosing branch condition, builder-pattern setters and callers. “Where is X set?” returns file:line evidence instead of a guess.
  • Message-stream reference index: resolves producer and consumer code for each stream topic. When a topic can’t be resolved, it is marked unresolved or ambiguous instead of guessed.
  • Delta indexing by git blob hash, so refreshes only touch changed files. A health check catches empty or stale indexes.

Why This Approach

I picked SQLite over a hosted vector database because it has zero infrastructure, is portable and is fast enough. Extraction patterns are stored as data, not code, so supporting a new framework idiom means adding a pattern instead of rewriting the logic. The design rule was “never guess”: every answer has to point to a line of code.

Outcomes

  • Cut LLM token use for code questions by 10 to 100 times compared with raw grep.
  • Became the default code-search layer for all lineage and impact-analysis work in the workspace.
  • Found and fixed a subtle index-integrity bug (chunk hashes ignored the repository, so re-indexing one repo silently emptied another). Added a health check that now runs after every bulk index.

Lessons

Precision beats recall for tooling that AI agents rely on. An honest “unresolved” is worth more than a confident wrong answer.
