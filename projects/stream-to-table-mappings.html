Stream-to-Table Mapping Generator

The catalog needed about 100,000 mappings that no one could build by hand. I generated and verified them, and flagged thousands of existing errors.

  • Python
  • polars/pandas
  • Protobuf metadata
  • Ingestion YAML
  • Excel output

The Problem

Event streams (Kafka topics carrying protobuf messages) land in a lakehouse across several layers: raw, staging and end-of-day/start-of-day snapshots. The data catalog needed field-to-column mappings between every stream and its tables, about 100,000 of them, and no one could build that by hand.

What I Built

A one-command pipeline that generates and verifies the mappings:

  1. Extracts the current stream and table inventory.
  2. Reads the ingestion configuration to learn which layers each topic actually lands in.
  3. Generates mappings at four levels: topic, schema, event and field.
  4. Runs a reconciliation pass to recover field mappings the generator missed. Every recovered mapping is checked against the live table catalog.
  5. Writes a workbook with one tab per level, plus a list of existing catalog relations that should be removed.

Why This Approach

Zero guessing. An early version broke ties heuristically, and an audit showed this created cross-domain misattributions (for example, an unanchored suffix match tied one topic to another’s table). Each heuristic was replaced with an exact rule, such as “the proto package must match” or “only map to layers the ingestion config ingests”. Every change was diffed against the previous baseline.

Outcomes

  • About 120,000 verified mappings across all levels. Every row in the deliverable is a confirmed match.
  • Found thousands of incorrect relations already in the catalog and produced a removal list.
  • Versioned releases with a changelog, so each count change can be explained.

Lessons

Baseline diffs are the best regression test for a data pipeline. If a count moves, you should be able to say exactly why.
