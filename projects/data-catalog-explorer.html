Data Catalog Explorer: a Governance “Super-App”

The governance team answered everyday questions with a dozen scripts and spreadsheets. I gave them one app built around the questions they actually ask.

  • Python
  • Flask
  • React 18
  • Vite
  • DuckDB
  • Gunicorn
  • Monaco editor
  • JWT/OIDC

The Problem

The enterprise data catalog held hundreds of thousands of assets and millions of attributes and relations, but the vendor UI made cross-cutting questions slow to answer. For example: which fields have no business term, which data streams have drifted from their schema, or what feeds a given table. The data governance team was using about a dozen separate scripts and spreadsheets to answer them.

What I Built

One Flask backend serving a React single-page app that brings together about ten tools:

  • Landing dashboard: coverage KPIs by asset type and application, with click-through drill-downs.
  • SQL IDE: Monaco editor, schema tree and query history over a local catalog snapshot.
  • Schema-vs-catalog comparisons: message schemas and OpenAPI specs compared against what the catalog records.
  • Asset mind map and lineage view: click to expand any asset’s relations and recorded field mappings.
  • Data availability explorer: table context, columns, samples, record counts and data quality rule runs.
  • DQ job manager and admin panel: snapshot upload, health monitoring, signed-in identity.

Why This Approach

Queries run against a local DuckDB snapshot instead of the live catalog API, which makes them sub-second and puts no load on production. Each sub-app is a self-contained backend module with its own React page, so tools can be added without touching the others. Navigation and app metadata are defined in one place.

Outcomes

  • Replaced a collection of ad hoc scripts with one deployed, authenticated app.
  • Questions that used to take hours of spreadsheet work now take seconds.
  • Backed by unit tests, invariant evals and a headless-browser smoke test that runs before each release.

Lessons

A unified UI matters as much as features. Restyling every tool onto one shared design system made the suite feel like a single product, and adoption went up.
