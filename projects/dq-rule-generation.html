Lineage-Driven Data Quality Rule Generation

Data quality rules were written by hand and often pointed at the wrong tables. I led an AI approach that writes them from plain-English business rules and recorded lineage.

  • SQL (Trino)
  • Python
  • LLM (Claude via AWS Bedrock)
  • Hybrid search
  • Data quality platform

The Problem

Data quality rules, such as “positions in system A must reconcile with system B” or “every margin charge must have a matching base record”, were written by hand. That was slow, inconsistent, and often wrong about which tables and columns actually hold the data.

What I Built

Two complementary pieces:

  1. A reusable DQ-rule skill for AI agents. Given a business rule, it looks up the recorded lineage between source and target, then generates a matched pair of SQL queries: a dataset query and a failing-rows query. It follows standard conventions (business-date handling, holiday-calendar CTEs), and every rule file ends with a written explanation of its logic and caveats.
  2. A natural-language DQ assistant. It turns plain-English questions into SQL using few-shot pattern learning and hybrid search over tens of thousands of indexed schema assets for column matching. It also has cost monitoring and feedback capture.

Why This Approach

Starting from lineage, not table-name guesses, means the rule compares the columns that are actually connected. Hybrid search (keyword plus semantic) found the right columns more cheaply than sending everything to the LLM.

Outcomes

  • Reconciliation rules validated against real test environments. One rule found a business-logic subtlety: a published total already included an add-on charge.
  • In the natural-language assistant, pattern learning raised SQL-generation accuracy from about 82% to 91%. Hybrid column matching cut cost by about 70% and latency by about 60%.
  • Running cost stayed well under budget, at a few dollars a month.

Lessons

Keep the generator simple and put the knowledge in a learnings file. Each validated rule makes the next one better.
