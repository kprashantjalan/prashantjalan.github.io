Engineering a Reliable AI-Agent Workspace

AI agents made confident mistakes and ran up costs. I set up the rules, tools and checks that made them dependable enough for real deliverables.

  • Claude Code
  • Modular rules
  • Skills
  • Evals
  • Git hooks
  • REST tooling

The Problem

LLM coding agents are powerful, but on enterprise analysis work they fail in predictable ways. They fabricate plausible names, burn tokens re-reading files, spawn expensive sub-agents for simple lookups, and lose work that was never committed. Early on, a couple of days of unconstrained usage cost hundreds of dollars.

What I Built

A workspace that treats the agent like a team member with an operating manual:

  • Modular rules: a short core policy file plus path-activated rule files that load only when work touches a given system, which keeps context small.
  • Skills: packaged, versioned procedures (lineage extraction, DQ rules, mapping-spec verification, Excel styling) with a registration and audit checklist.
  • Tooling over brute force: agents query a code-search API and a catalog database instead of grepping raw files.
  • Guardrails: banned destructive commands, sub-agents only with explicit approval, commit after every completed task, and pre-commit hooks that block work outside the workspace.
  • Evals for every change: invariant checks with planted-violation self-tests and one-time mutation tests.
  • Persistent memory: small, linked memory files that record decisions and corrections so they carry across sessions.

Why This Approach

Every rule came from a real incident: lost files, a runaway sub-agent, a fabricated mapping. Writing the lesson down where the agent will read it is the cheapest way to make sure it never happens again.

Outcomes

  • Big cut in token waste, through anti-duplication rules and API-first search.
  • Repeatable, auditable deliverables, because every change ships with evals and every claim with evidence.
  • A disaster-recovery path: two commands restore the workspace and 150+ repository clones.

Lessons

Reliability with AI agents is mostly an environment-design problem: clear rules, good tools, fast checks.
