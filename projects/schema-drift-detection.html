Schema-vs-Catalog Drift Detection (CDC)

Nobody knew how far the catalog had drifted from reality. I made the gap measurable and repeatable for the governance team.

  • Python
  • Flask
  • JavaScript/React
  • SQLite
  • DuckDB
  • CSV diffing

The Problem

Message schemas evolve in a schema-governance repository, and the data catalog is supposed to mirror them. Over time the two drift apart: new fields go unregistered, retired fields stay in the catalog, and flags such as “optional” or “deprecated” disagree. Nobody knew how big the gap was.

What I Built

A change-data-capture comparison tool:

  • Extraction: pulls the latest schema metadata from the artifact repository and generates normalized CSVs for seven asset levels (schema set → topic → event → sub-message → field, and so on).
  • Comparison core: one module holds every comparison rule (shared columns, exclusions, nullable-flag handling, path and case normalization) and reports both completeness (what is missing) and accuracy (what differs).
  • UI: side-by-side diff highlighting, coverage statistics, and exports split into source-only, catalog-only and changed records.
  • Refresh and history: on-demand database refresh with backup rotation and change tracking.

Why This Approach

Earlier versions had several comparison paths that disagreed with each other. Consolidating to one comparison path removed that whole class of bug. Invariant checks run on the delivered files themselves, which caught issues such as inconsistent boolean spellings between sources and a view that only diffed the first 5,000 rows.

Outcomes

  • Loads and diffs datasets of 16,000 to 31,000 rows in about 7 seconds.
  • Gave the governance team a measurable, repeatable drift report instead of guesses.
  • Refactored hard-coded values into shared constants, verified byte-for-byte against the old output with zero behavior change.

Lessons

Read your own dashboards skeptically. Several real bugs were found just by asking why a number looked too round.
